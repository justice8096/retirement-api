# Social Security 2032 Scheduled-Cut Modeling — Design

Date: 2026-08-29 · Status: approved · Scope: engine + API + dashboard + MCP

## Problem

The engine models Social Security inside a lump `monthlyIncome` that grows
smoothly at `incGrowth`. Trust-fund depletion is projected for ≈2032–2033
(Trustees ≈2033; CRFB post-Fairness-Act ≈2032), at which point scheduled
benefits drop ~21–24% automatically absent congressional action. The
simulator currently cannot represent that cliff, so success rates and safe
withdrawal numbers are optimistic for any plan leaning on SS past 2032.

Decision (approved): **model the cut in the engine AND surface it visibly**
(chart marker, report callout, assumptions toggle).

## Approach

First-class SS params in the engine (Approach A). Rejected: compiling the
cut into the dormant `incomeChange` LifeEvent (a fixed `monthlyDelta` cannot
express a percentage cut of a stream that has been growing at `incGrowth`);
caller-side-only (no engine change can express a mid-sim cliff).

## Engine — `shared/engine/monte-carlo.ts` (canonical here)

Three new optional `MonteCarloParams` fields, all no-op when absent
(bit-identical legacy behavior, same pattern as the brokerage-fee fields):

```ts
/** Portion of monthlyIncome that is Social Security (USD/month, today's $).
 *  Clamped to [0, monthlyIncome]. Grows at incGrowth alongside income. */
ssMonthlyIncome?: number;
/** Sim year (0-indexed) at which the scheduled SS benefit reduction fires.
 *  Negative = cut already in effect at retirement start (applied at year 0). */
ssCutYear?: number;
/** Fraction of the SS benefit REMAINING after the cut. Default 0.77 (23% cut). */
ssCutFactor?: number;
```

Kernel: track `ssIncome` parallel to `income` (both `*= 1 + incGrowth`
yearly). At the first sim year `>= ssCutYear`, apply once:
`income -= ssIncome * (1 - ssCutFactor); ssIncome *= ssCutFactor`.

Survivor phase: `survivorMonthlyIncome` is typically pure SS (max PIA), so
when the cut year has passed, the survivor income is multiplied by
`ssCutFactor` in full. **Documented v1 simplification** — a future
`survivorSsMonthlyIncome` split can refine it.

Interactions: part-time income unaffected (separate stream). One-time
incomes unaffected. `incGrowth` continues to apply to the reduced stream.

## API — `POST /api/simulate` (`src/routes/simulate.ts`)

New optional schema fields:

| Field | Type/range | Default |
|---|---|---|
| `ssAnnualIncome` | 0..annualIncome (validated) | 0 (no cut modeled) |
| `ssCutCalendarYear` | int 2026..2100 | 2032 |
| `ssCutPct` | 0..1 (decimal fraction, docs style) | 0.23 |

Translation: `ssCutYear = ssCutCalendarYear - currentCalendarYear`, may be
negative (engine treats as already-cut at year 0). `ssMonthlyIncome =
ssAnnualIncome / 12`, `ssCutFactor = 1 - ssCutPct`. The response `inputs`
echo includes all three so callers can label charts. `_units` note per API
style: `ssCutPct` is a decimal fraction.

Validation: `ssAnnualIncome > annualIncome` → plain-language 400 via the
standard envelope ("Social Security income cannot exceed total income").

## Dashboard — `rda-consolidation` (branch `consolidation`)

- **Assumptions screen**: "Model scheduled Social Security reduction"
  toggle, default ON; editable year (2032) and percent (23%). Plain-language
  helper text; add glossary entry (server-side, `/api/glossary`) explaining
  trust-fund depletion, citing Trustees/CRFB, per house a11y style.
- **Monte Carlo + report screens**: vertical marker at the cut calendar
  year on balance-path charts with callout ("Scheduled SS reduction —
  benefits fall N% absent congressional action"). Marker renders only when
  the toggle is ON and SS income > 0.
- SS slice sourced from existing member data (`ssAnnual` fill already
  exists). Client-side engine calls pass the same three params — numbers
  and marker always agree.

## MCP — `retirement-mcp`

`run_scenario` gains the three optional fields, passed through to
`/api/simulate`. Defaults live server-side; MCP sends only what the caller
sets.

## Tests (written first; `npm run test:shared` + drift gate)

Engine: no-op when unset (bit-identical to baseline seed run); cut fires at
exactly `ssCutYear`; negative/zero `ssCutYear` = cut from year 0;
`ssMonthlyIncome` clamped to `monthlyIncome`; growth applies to reduced
stream; survivor-phase factor; part-time unaffected.
API: schema defaults; calendar translation (mocked clock); already-retired-
past-2032 edge; validation envelope for SS > total income.
Dashboard: toggle wiring; marker visibility rules.

## Out of scope

- Per-member SS cut modeling (household lump only, v1).
- IRC §86 tax interaction with the reduced benefit (main-branch tax work;
  reconcile at the consolidation↔main merge).
- Any change to stored `/api/me/financial` fields (`ssAnnual` already
  exists and suffices).

## Known risk

Dashboard worktrees diverged (consolidation 3 ahead / 8 behind main; main
holds SS-aware tax work). This feature builds on consolidation per its
"sole dashboard" declaration; the merge debt is flagged for a separate
reconciliation session.
